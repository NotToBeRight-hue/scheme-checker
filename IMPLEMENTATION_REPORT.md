# Implementation report

Verified on **2026-10-12, Asia/Kolkata**, on Windows using Java 17.0.19, portable Node 24.21.0, Maven Wrapper 3.3.4 / Maven 3.9.11 and actual MySQL 8.4.11. The application is implemented and locally verified as a v3 prototype. No genuine government schemes were verified, seeded or approved.

## Delivered implementation

Read CODEX_START_HERE.md, README.md and all original files in docs/ before implementation. Implemented all baseline citizen and lean admin workflows using real same-origin APIs, plus the additional DTOs/routes documented in docs/IMPLEMENTED_CONTRACTS.md. The frontend supports the specified light/dark colors, system initial theme and saved theme, labeled controls, keyboard focus, skip navigation, mobile layouts, pagination, loading/saving feedback, empty/error/validation/conflict and success states.

The backend implements controlled admin provisioning, citizen registration/login/logout, 15-minute HS256 HttpOnly-cookie sessions, rotating cookie/header CSRF, backend RBAC/ownership and current ACTIVE-user checks, IP/account login limits and sanitized admin/security audits. Passwords use SHA-256 prehashing followed by BCrypt to preserve the specified full 8?128-character range. Default Spring in-memory users/basic/form authentication were disabled.

Flyway creates exactly the eleven canonical domain tables with BIGINT UNSIGNED AUTO_INCREMENT IDs, FKs, unique constraints, indexes and checks. MySQL triggers reject updates/deletes to evaluation snapshots and published rule versions. JPA handles aggregate CRUD; JDBC is used for read-only dashboard projections. Runtime transactions use READ_COMMITTED and locking refreshes for profile/answer changes, evaluation saving and atomic publication. Revisions advance once, stale requests conflict without retry, shared answers are preserved when omitted and unrelated/duplicate/invalid answers are rejected.

The deterministic engine validates rule shape/depth, types, field/operator combinations, unique leaf IDs and active/linked questions; evaluates every leaf with TRUE/FALSE/UNKNOWN; uses exact BigDecimal comparison, inclusive ranges and completed age with the specified provisional leap-day behavior. Decision-critical unknowns return 422 with missing keys and no history. Immutable history includes facts/rules/explanations and computed profile, rule and relevant age staleness.

The development seed contains eight explicitly fictional synthetic schemes. Production hides synthetic catalog records and refuses synthetic publication. Genuine publication is gated on official HTTPS gov.in/nic.in source, verification date, per-leaf source sections, documented exceptions and reviewer approval. Suggestion acceptance does not publish; explicit conversion creates only a draft.

## Failures found and repaired

- npm 10 failed dependency resolution with an internal edgesOut error; retried under the required Node 24 runtime and pinned successfully.
- Initial MySQL download URLs returned 404; official 8.4.11 download succeeded.
- Missing CSS Modules types and Windows non-UTF-8 source encoding broke the first frontend build; added Vite client types and normalized UTF-8.
- Spring Boot 4 Flyway auto-configuration needed its modular starter; added it. A password-encoder subclass was incompatible with the runtime's final methods; replaced it with PasswordEncoder composition.
- MySQL rejected nullability changes after FK installation; moved changes before constraints. Trigger creation with binary logging required global privileges; isolated development MySQL/Compose use --skip-log-bin, with production migration privileges documented.
- Concurrent profile writes both succeeded with a nonlocking refresh; locking refresh plus READ_COMMITTED now yields one success and one conflict. Additional evaluation/publication races pass.
- Spring's MockMvc csrf helper replaced the actual cookie repository during the suite; tests now send genuine double-submit cookies/headers without replacing server configuration. Real CSRF bootstrap/rotation and browser mutations pass.
- Browser select labels included option text; controls now have explicit labels/IDs. Browser assertions were made precise for simultaneous loading/success live regions.
- Windows held the running JAR/native Vite dependency during verify/npm ci; stopped those task-owned servers, reran successfully, and restarted them. Browser-mode verification avoids dependency reinstalls and JAR repackaging while servers are running.
- Inherited DEBUG environment caused excessive framework output; scripts set DEBUG=false, logging is restricted and default generated Spring security credentials are disabled.

## Explicitly unrun checks and prototype limits

Docker is unavailable in this environment. **Docker Compose startup and the Testcontainers branch were not executed.** A callable Testcontainers MySQL path is included (`USE_TESTCONTAINERS=true`); all executed persistence/migration tests used real portable MySQL 8.4.11, never H2. Compose's separate test-schema initialization is source-reviewed but not runtime-verified here.

No real HTTPS deployment, reverse-proxy deployment, distributed rate limiter/load test, full WCAG/screen-reader audit or the deferred 88 extended cases was run. Secure-cookie behavior is implemented based on HTTPS request state, but a live TLS deployment is not claimed tested. An additional scripted post-restart HTTP login probe was rejected by tool policy and did not run; database persistence is established by the successful restart/count comparison and no passing result is claimed for that extra probe.

This is a single-process local prototype: login windows reset with application restart; logout clears the browser cookie and a previously copied JWT remains valid until its 15-minute expiry. Production must use HTTPS, non-dev/test profiles, strong private secrets, verified scheme sources, restricted runtime database permissions and separate migration credentials. ISO dates/UTC times use validated string columns; published metadata is intentionally frozen, as documented in the supplemental DTO contract. Genuine source verification remains an explicit human reviewer responsibility; no real scheme is approved by this implementation.
